## 一、设计原则

1. **单用户本地工具，效率优先**：去掉了登录、权限、多端适配等负担，桌面端宽屏为主，信息密度可适当高一些，减少跳转层级。
2. **身份分流**：进入某行动营后，依据身份（学员/志愿者）展示完全不同的工作台，避免功能交叉干扰。
3. **AI 生成结果可干预**：所有 AI 产出（学习路线、打卡内容、评改结果）都默认可编辑，强调"人工确认为准"，符合 MVP 前期把控质量的需求。
4. **降级可见**：依赖破局接口的能力（自动提交、自动同步、打卡进度读取）在不可用时，UI 上明确提示降级方式，不静默失败。
5. **状态即反馈**：行动营进度、打卡天数、评改状态、Token 状态等用徽章/进度条实时呈现，使用者一眼掌握全局。

## 四、设计规范

### 4.1 配色

| 用途 | 变量 | 色值 | 说明 |
| --- | --- | --- | --- |
| 主色 | `--primary` | `#4f46e5` | 靛蓝，用于主按钮、选中态、链接强调 |
| 主色浅 | `--primary-light` | `#eef2ff` | 选中项背景、提示条 |
| 背景 | `--bg` | `#f6f7fb` | 页面底色 |
| 表面 | `--surface` | `#ffffff` | 卡片/侧边栏背景 |
| 文字主 | `--text` | `#1f2937` | 正文 |
| 文字次 | `--text-sub` | `#6b7280` | 副标题、说明 |
| 文字浅 | `--text-light` | `#9ca3af` | 占位、辅助 |
| 成功/有效 | `--success` | `#16a34a` | 有效打卡、已评改、Token正常 |
| 警告/待办 | `--warning` | `#d97706` | 待评改、打卡不足提醒 |
| 危险/无效 | `--danger` | `#dc2626` | 无效打卡、删除、错误 |
| 星级 | `--star` | `#f59e0b` | 打卡星级（金色） |

### 4.2 身份徽章配色

| 身份 | 背景 | 文字 |
| --- | --- | --- |
| 学员 | `#dbeafe`（浅蓝） | `#1d4ed8` |
| 志愿者 | `#fce7f3`（浅粉） | `#be185d` |

> 用蓝/粉区分学员/志愿者，与主色（靛蓝）拉开层次，侧边栏行动营标签与列表徽章一致。

### 4.3 字体与字号

- 字体栈：`-apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC", "Microsoft YaHei", sans-serif`
- 等宽（Token/代码）：`monospace`
- 字号层级：
  - 页面标题 20px / 700
  - 卡片标题 14px / 600
  - 正文 13~14px
  - 副标题/说明 12~13px（`--text-sub`）
  - 标签/徽章 11px

### 4.4 圆角与间距

- 圆角：卡片 `10px`，输入/按钮/小元素 `6px`，徽章 `10px`(胶囊) / `5px`
- 间距基准 `8px`，常用 8/12/16/20/24
- 阴影：默认 `0 1px 3px + 0 1px 2px`（轻量），悬浮/弹层加重

### 4.5 通用组件

| 组件 | 说明 |
| --- | --- |
| 徽章 badge | 状态标记：绿=成功/有效，橙=待办/警告，灰=中性/已结束，红=无效/危险，蓝=信息/学员 |
| 进度条 progress | 训练进度、打卡进度，主色填充 |
| 星级 stars | 金色实心★ + 灰色空心★；评改时为可点击选择 star-pick |
| 开关 switch | 手动/自动提交等二态切换 |
| 卡片 card | 白底圆角带阴影，承载一个功能区块 |
| 统计卡 stat | 大数字 + 标签，用于看板顶部概览 |
| 时间线 timeline | 学员档案历史打卡展示 |
| 折叠区 collapsible | 档案参考、评分标准等可折叠 |
| 上传区 upload-zone | 虚线边框，拖拽/点击上传 |
| 提示条 note-banner/help-bar | 黄色提示/蓝色引导，传达降级与说明 |

## 五、核心交互流程

### 流程 A：学员打卡（主链路）

```
行动营列表 ──选学员营──▶ 学员·今日看板
                           │
                           │ 点击"生成今日打卡"
                           ▼
                      学员·打卡生成
                           │
            ┌──────────────┼──────────────┐
            │ 输入今日所做（文字+图片）      │
            │ 设置提交方式开关（手动/自动）   │
            │ 点击"生成打卡内容"            │
            ▼                              │
        AI 生成四板块（今日行动/收获/好事/下一步）
            │                              │
            │ 可编辑修改 / 重新生成          │
            ▼                              │
        ┌─── 提交方式 ───┐                 │
        │ 手动(默认)      │ 自动            │
        │ 复制到剪贴板    │ 调接口自动提交   │
        │ → 粘贴到破局页面 │                 │
        └────────────────┘                 │
```

**关键交互**：
- 提交方式为**开关**，默认关闭（手动），文案与按钮随开关状态变化（手动=复制内容；自动=确认并自动提交）。
- 自动提交依赖破局写接口，不可用时强制手动并提示。
- 生成结果区有状态徽章：生成中（橙）→ 已生成（绿）。

### 流程 B：志愿者作业评改（主链路）

```
志愿者·学员看板 ──点"去评改"──▶ 作业评改
                                  │
                  ┌───────────────┼───────────────┐
                  │ 左：待评改列表（选学员）        │
                  │ 右：评改详情面板                │
                  │   1. 学员本次打卡内容           │
                  │   2. 该学员历史档案（折叠参考） │
                  │   3. AI评改结果（星级+评语+依据）│
                  │   4. 评分标准（折叠参考）       │
                  ▼                              │
            可修改星级/评语                       │
                  │                              │
                  ▼                              │
          [确认并同步到破局] → 调写接口 → 写入档案
```

**关键交互**：
- 评改面板**必须展示历史档案参考**（默认展开），体现"参考历史判断进步/原创性"。
- 星级为可点击选择，选中后显示"X星 · 有效/无效打卡"。
- "确认并同步"调用破局打分接口；同步成功后该条标记已评改并写入档案。
- 提供"仅保存不同步""重新生成评改"，应对降级与重评场景。
- 支持批量确认（增强项）。

### 流程 C：创建行动营

```
行动营列表 ──新建──▶ 创建行动营
                        │
        选身份(学员/志愿者,卡片单选,不可改)
        录入：名称、简介、总天数、起止、最低打卡天数
                        │
                 总天数变化 → 自动算最低天数(×0.6)
                        │
                        ▼
              创建 → 跳转对应身份工作台
              学员 → 今日看板（提示先上传手册）
              志愿者 → 学员看板（提示先配 Token）
```

### 流程 D：定时同步（志愿者看板）

```
本地定时任务（如每日 09:00）
      │
      ▼
调用破局读接口拉取学员打卡数据
      │
   ┌──┴──┐
 成功    失败(网络/401/接口异常)
  │       │
  ▼       ▼
更新学员档案/看板   提示失败原因(如Token失效请更新)
                  保留已有数据，支持手动"立即同步"重试
```

## 六、各页面详细说明

### P1 行动营列表（home）
- **入口页**，顶部统计（进行中/已结束/学员身份/志愿者身份数量）。
- 行动营以卡片展示：图标、名称、身份徽章、状态徽章、起止时间、训练进度条（Day x/N）、有效打卡进度或待评改数。
- 点击卡片进入对应身份工作台（学员→今日看板，志愿者→学员看板）。
- 已结束行动营半透明展示。

### P2 创建行动营（create）
- 身份选择为**卡片单选**，选中高亮，附说明文字。
- 总天数输入时实时计算"最低打卡完成天数"默认值（×0.6 四舍五入），可手动覆盖。
- 起止时间与总天数做合理性提示（不强制阻断）。
- 底部提示创建后下一步动作（学员→传手册；志愿者→配 Token）。

### P3 学员·今日看板（student-dashboard）
- 顶部统计：训练 Day、有效打卡（X/18）、距退押金差值、2★以下次数。
- **今日任务卡**：Day N 任务标题+描述+标签（手册章节/类型/预计时长），主按钮"生成今日打卡"跳转 P5。
- **本周预览**：Day5~Day7 任务列表，今天高亮。
- 早于开始/晚于结束日期时，展示"未开始/已结束"提示（原型以进行中为例）。

### P4 学员·学习路线（student-route）
- 顶部"重新规划"按钮（带覆盖确认提示）+ 手册入口。
- 顶部蓝色提示条：说明手册无固定结构、路线由 AI 自主规划、可编辑。
- 每日任务列表：Day 标签 + 标题 + 描述 + 编辑按钮；今天项高亮（主色浅底）+ "去打卡"快捷；已完成项灰显。
- 单日任务可展开编辑（MVP 可行内编辑）。

### P5 学员·打卡生成（student-checkin）
- **左右两栏**：左输入，右结果。
- 左栏：文字描述（textarea）、图片上传区、提交方式开关（手动/自动）、"生成打卡内容"主按钮。
- 右栏：四板块卡片（今日行动/今日收获/好事分享/下一步行动，主色小标题），状态徽章（生成中→已生成），编辑/重新生成按钮，提交按钮（随开关变文案）。
- 底部：本期打卡记录表（日期/Day/核心行动/星级/状态）。

### P6 志愿者·学员看板（volunteer-dashboard）
- 顶部统计：带教学员/待评改/今日已打卡/打卡不足需提醒。
- 顶部操作：定时同步频率说明 + "立即同步"。
- 筛选 Tab：全部/待评改/打卡不足/已评改（带数量），附搜索框。
- 学员表格：昵称、已打卡Day、有效天数、距目标、最近星级、状态、操作（去评改/查看档案）。
- 打卡不足的"距目标"列加 ⚠ 提醒。

### P7 志愿者·作业评改（volunteer-grade）
- **左右两栏**（280 + 自适应）：
  - 左：待评改学员列表（选中项高亮），显示昵称/Day/主题。
  - 右：评改详情，自上而下四块卡片：
    1. 学员本次打卡内容（只读展示）+ "查看完整档案"入口。
    2. 历史档案参考（默认展开的时间线，含历史星级与评语）。
    3. AI 评改结果：星级（可点选）、评语（可编辑）、维度得分依据、评分标准（折叠）。
    4. 操作：确认并同步 / 仅保存不同步 / 重新生成。
- 顶部显示待评改总数 + 批量确认。

### P8 志愿者·学员档案（volunteer-archive）
- 顶部黄色提示条：档案仅志愿者可见。
- 统计：学员昵称、有效打卡、距目标、平均星级。
- 时间线：逐日打卡内容摘要 + 星级 + 评语；待评改项标橙，无效项评语区标红底。
- 底部"为 Day8 打卡评改"快捷回到 P7。

### P9 手册管理（manual）
- 顶部黄色提示：手册与主流程解耦，需自行 OCR 后上传。
- 当前手册卡：文件名/上传时间/字数/章节数 + 预览/删除。
- 上传区：Tab 切换"上传文件 / 粘贴文本"；拖拽上传区；支持 .md/.txt。
- 手册预览卡：前 500 字预览。
- 提示替换后建议重新规划学习路线。

### P10 评分标准（scoring）
- 全局配置，顶部"保存"按钮。
- **评分维度表**：维度/说明/是否依赖学员档案/编辑，可添加维度。
- **星级判定规则**：三档输入框（三星/二星/一星判定描述）。
- 提示：有效打卡=≥2星；修改对后续评改生效，不回溯重评。

### P11 接口配置（settings）
- **Token 配置卡**：Authorization 密码框输入、接口地址（预留）、Token 状态（正常/失效 + 上次校验时间）、保存/测试连接。
- 提示 Token 过期与 401 处理。
- **接口能力清单表**：接口名/读写类型/用途/状态（已验证/待确认），列出已知接口（拉取打卡、作业打分）与待确认接口（提交打卡、读取进度），呼应 PRD 待确认项。

## 七、状态机与徽章约定

### 7.1 行动营状态
| 状态 | 徽章 | 判定 |
| --- | --- | --- |
| 未开始 | 灰 | 当前日期 < 开始时间 |
| 进行中 | 绿 | 开始 ≤ 当前 ≤ 结束 |
| 已结束 | 灰 | 当前 > 结束时间 |

### 7.2 打卡/评改状态
| 状态 | 徽章 | 说明 |
| --- | --- | --- |
| 待评改 | 橙 | 学员已提交，志愿者未评改 |
| 已评改·有效 | 绿 | 星级 ≥ 2 |
| 已评改·无效 | 红 | 星级 = 1 |
| 已提交·待评改 | 橙 | 学员侧已提交，等待结果 |
| 今日未打卡 | 灰 | 志愿者看板，学员今日未提交 |
| 打卡不足 | 红 | 有效天数落后，需提醒 |

### 7.3 接口/Token 状态
| 状态 | 徽章 |
| --- | --- |
| 正常/已配置 | 绿 |
| 待确认/未配置 | 灰 |
| 失效/异常 | 红 |

## 八、降级场景的 UI 表现

对应 PRD 第九章降级方案，UI 上如何呈现：

| 场景 | UI 表现 |
| --- | --- |
| 自动提交接口不可用 | P5 提交开关强制关闭且禁用，提示"自动提交暂不可用，请手动复制提交" |
| 评改同步接口不可用 | P7 "确认并同步"按钮置灰，提示改用"仅保存不同步" + 手动复制星级评语；保留结果待恢复后补同步 |
| 读接口/Token 失效 | P6 同步失败提示条（红）"Token 可能失效，请到接口配置更新"；保留已拉取数据；"立即同步"可重试 |
| 手册未上传 | P3/P4/P5/P7 相关 AI 功能处提示"未配置手册，建议上传"，功能可降级运行 |
| AI 生成失败 | 生成按钮区提示失败 + 重试，不影响已有数据 |

## 九、原型使用说明

1. 用浏览器打开 `ui-prototype/index.html`。
2. 左侧侧边栏点击导航项切换页面；点击行动营名可展开/折叠该营子导航。
3. 首页（行动营列表）点击卡片亦可进入对应工作台。
4. 可交互元素：
   - **创建行动营**：身份卡片单选、总天数自动算最低打卡天数。
   - **打卡生成**：提交方式开关（文案随状态变化）、生成按钮（模拟生成中→已生成）、提交按钮（手动/自动不同提示）。
   - **作业评改**：星级可点击选择、档案/评分标准折叠展开、确认同步弹窗。
   - **手册管理**：上传/粘贴 Tab 切换。
   - **接口配置**：测试连接弹窗。
5. 原型数据为示例数据（两个进行中行动营 + 一个已结束），仅作展示，不代表真实数据。
