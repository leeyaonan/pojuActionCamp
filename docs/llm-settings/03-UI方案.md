## 3. 交互流程

### 3.1 编辑厂商（Modal）

点击「编辑」→ 弹出 Modal：

| 字段 | 控件 | 说明 |
|------|------|------|
| 厂商名称 | Input | 预置厂商禁用编辑（只读） |
| 接入地址 | Input | base_url，必填 |
| 协议 | Select | 本期固定 `openai_compatible`，只读展示 |
| 模型 | Select（可编辑） | 选项来自 `models` 字段，允许手动输入自定义模型名（`showSearch + tags`） |
| API Key | Input.Password | 占位「粘贴该厂商的 API Key」；已配置时提示「当前：sk-****abcd，留空表示不修改」 |
| 可选模型列表 | Select（tags 模式） | 可选维护，供模型下拉用 |

- 保存：`PUT /providers/{id}`，`api_key` 留空则不传（后端不动）
- 保存后：`invalidateQueries(['llm','providers'])`，Key 状态置 `unknown`

### 3.2 测试连接

点击「测试」→ 该行 loading → `POST /providers/{id}/test`：
- 成功：toast「连接成功」，状态变「可用」
- 失败：toast 错误信息（如「Key 失效」「连接超时」），状态变「失效」

### 3.3 激活 / 切换

点击「激活」（仅 `key_status=valid` 可点，否则 disabled + tooltip「请先测试通过」）：
- `POST /providers/{id}/activate`
- 成功后：列表刷新，该行「激活」列变「当前」（高亮 Tag），其余变「激活」按钮
- 顶部「当前使用」卡同步更新
- toast「已切换到 XXX」

### 3.4 新增厂商

点击「+ 新增厂商」→ 弹 Modal（同 3.1，但名称可填）→ `POST /providers`。
用于接入预置 4 家之外的自建中转 / 其他厂商。

### 3.5 删除厂商

操作列「删除」（预置厂商不显示删除按钮）→ Popconfirm「确认删除 XXX？」→ `DELETE /providers/{id}`。
若删除的是当前激活厂商：Popconfirm 二次提示「该厂商当前已激活，删除后将回退到 .env 配置，确认？」

## 4. 组件设计

### 4.1 厂商列表表格（Table）

| 列 | dataIndex | 宽 | 渲染 |
|----|-----------|-----|------|
| 厂商 | name | 120 | 文本 + 预置标记（小 Tag「预置」） |
| 协议 | protocol | 140 | 文本（`openai_compatible` → 「OpenAI 兼容」） |
| 接入地址 | base_url | 280 | 文本（超长省略 + tooltip） |
| 模型 | model | 160 | 文本 |
| Key 状态 | key_status | 110 | 复用 `StatusTag`：valid=可用(normal)、invalid=失效(error)、unknown=未配置(unknown) |
| 激活 | is_active | 90 | is_active=True → 绿色 Tag「当前」；False → 「激活」按钮 |
| 操作 | — | 200 | [编辑] [测试] [删除]（预置无删除） |

行样式：`is_active=True` 的行加浅色背景 `var(--bg)` 高亮。

### 4.2 当前使用卡

- 无激活厂商时：显示「未激活任何厂商，当前回退 .env 配置（{settings.llm_provider}/{llm_model}）」+ Alert(type=warning)
- 有激活厂商时：厂商名 + 模型 + 状态 Tag + 上次校验时间

### 4.3 状态复用

复用 `frontend/src/components/Tag.tsx` 的 `StatusTag`（破局页已用），保证状态徽标视觉一致。

## 5. 状态管理（react-query）

```ts
// hooks/useLLMSettings.ts
export const llmKeys = {
  providers: ['llm', 'providers'] as const,
  active: ['llm', 'active'] as const,
};

export function useLLMProviders() {
  return useQuery({ queryKey: llmKeys.providers, queryFn: llmApi.listProviders });
}
export function useActiveProvider() {
  return useQuery({ queryKey: llmKeys.active, queryFn: llmApi.getActive });
}
export function useUpdateProvider() {
  const qc = useQueryClient();
  return useMutation({
    mutationFn: ({ id, payload }) => llmApi.updateProvider(id, payload),
    onSuccess: () => {
      qc.invalidateQueries({ queryKey: llmKeys.providers });
    },
    onError: toastOnBizError,
  });
}
// useCreateProvider / useDeleteProvider / useTestProvider / useActivateProvider 同理
// activate / test 成功后额外 invalidate llmKeys.active
```

## 6. 边界态

| 状态 | 展示 |
|------|------|
| 列表加载中 | Table `loading=true`（Spin） |
| 列表为空（不应发生，预置自愈） | Empty「暂无厂商配置，点击新增」 |
| 测试中 | 该行操作列按钮 loading，禁用其他操作 |
| 激活中 | 按钮 loading |
| Key 未配置 | 「激活」按钮 disabled，tooltip「请先填写 Key 并测试通过」 |
| 后端未启动 | 复用全局 BizError toast「网络异常，请检查后端服务是否启动」 |

## 8. 视觉规范

- 复用 `Settings.tsx` 的样式：`borderRadius:10`、`background:var(--surface)`、`bodyStyle padding:20`
- 卡片标题 `fontSize:14 fontWeight:600`
- 页头标题 `fontSize:20 fontWeight:700`
- 副标题 `color:var(--text-sub) fontSize:13`
- 高亮激活行：`background:var(--bg)`
- 状态 Tag 复用 `StatusTag`，不引入新色彩

## 9. 与现有「接口配置」页的关系

- 两个页面平级，侧边栏相邻：「接口配置」（破局 Token） + 「AI 模型配置」（大模型）
- 视觉/交互范式完全对齐（卡片、StatusTag、测试连接、Popconfirm）
- 不合并为一个页面：两者职责清晰分离，且「接口配置」已有能力清单等专属内容
