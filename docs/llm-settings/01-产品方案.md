# AI 模型配置 — 产品方案

> 版本：v1.0　　日期：2026-07-04
> 关联：`技术方案文档(MVP).md` 6.2 / 8.2 / 11.5；`docs/apiDocs/MinimaxApi.md`

---

## 1. 背景与问题

当前平台底层大模型配置写死在 `backend/.env`：

```
LLM_PROVIDER=anthropic
LLM_API_KEY=sk-test
LLM_MODEL=claude-sonnet-4-6
```

存在两个问题：

1. **无可用 Key**：使用者没有 Anthropic 官方 API Key，手中只有国内厂商的 Key（MiniMax、DeepSeek、GLM、LongCat），导致所有 AI 能力（学习路线生成、打卡生成、作业评改）无法实际运行。
2. **无法运行时切换**：配置走 `.env`，修改后必须重启后端；且无法在 UI 上配置多套 Key、按需切换。

破局接口的 Token 已实现「DB 存储 + UI 配置 + 加密 + 测试连接」的成熟模式（见 `app/services/settings_service.py`），本功能将同一模式推广到大模型配置。

## 2. 目标

| # | 目标 |
|---|------|
| G1 | 在 UI 上手动配置多家大模型厂商的 API Key、接入地址、模型名 |
| G2 | 一键「激活」某一家厂商作为当前使用方，切换即时生效，无需重启 |
| G3 | 切换后，平台所有 AI 能力（路线生成 / 打卡生成 / 作业评改）调用该厂商模型 |
| G4 | API Key 加密存储、脱敏展示，支持连接测试 |

## 3. 非目标（本期不做）

- 不做用量/计费/Token 消耗统计
- 不做多厂商并发（同一时刻全局只有一个激活厂商）
- 不做模型微调 / 自定义模型训练
- 不做按任务类型路由到不同厂商（如评改用 A、生成用 B）

## 4. 用户故事

- **US1**：作为运营者，我打开「AI 模型配置」页，看到 4 家预置厂商（DeepSeek / GLM / MiniMax / LongCat），每家都带默认接入地址和推荐模型，我只需填入自己的 API Key。
- **US2**：我填好 DeepSeek 的 Key，点「测试连接」，系统发一条轻量探测请求，返回成功/失败与原因；成功后状态变为「可用」。
- **US3**：我点「激活」，DeepSeek 成为当前厂商，页面顶部「当前使用」卡显示 DeepSeek；之后生成学习路线、生成打卡、AI 评改都走 DeepSeek。
- **US4**：DeepSeek 余额耗尽后，我改填 GLM 的 Key 并激活，所有 AI 能力立刻切到 GLM，无需重启服务。
- **US5**：我新增一家自建中转（OpenAI 兼容协议），填自定义接入地址与模型名，测试通过后也能激活使用。

## 5. 功能清单

| 编号 | 功能 | 说明 |
|------|------|------|
| F1 | 预置厂商清单 | 首次进入自动种入 4 家厂商的默认配置（接入地址 + 推荐模型），Key 为空 |
| F2 | 厂商配置管理 | 新增 / 编辑 / 删除厂商配置；支持预置 4 家之外的自定义厂商 |
| F3 | API Key 加密存储 | Key 用 Fernet 对称加密入库，列表/详情仅展示脱敏形式（末 4 位） |
| F4 | 测试连接 | 用该厂商配置发一条轻量 chat 请求，校验 Key 与地址有效，更新状态 |
| F5 | 激活 / 切换 | 激活某厂商 → 全局仅一条 `is_active=True`；切换后 LLM 客户端单例失效重建 |
| F6 | 当前激活展示 | 页面顶部展示当前激活厂商、模型、状态；侧边栏可加状态徽标 |
| F7 | .env 兜底 | DB 无激活厂商时，回退到 `.env` 的 `LLM_*` 配置，保证向后兼容 |

## 6. 预置厂商清单

> 接入地址与模型名为「预置默认值」，用户可在 UI 编辑；以各厂商官方文档为准。

| 厂商 | 协议 | 接入地址（base_url） | 推荐模型 | 备注 |
|------|------|----------------------|----------|------|
| DeepSeek | OpenAI 兼容 | `https://api.deepseek.com` | `deepseek-v4-flash` | 另有 `deepseek-v4-pro` |
| 智谱 GLM | OpenAI 兼容 | `https://open.bigmodel.cn/api/paas/v4` | `glm-4.7-flash` | 另有 `glm-4.7`、`glm-5.2`、`glm-5-turbo` |
| MiniMax | OpenAI 兼容 | `https://api.minimaxi.com/v1` | `MiniMax-M3` | 同时支持 Anthropic 兼容（`/anthropic`） |
| LongCat | **Anthropic 兼容** | `https://api.longcat.chat/anthropic` | `LongCat-2.0` | 走 Anthropic Claude API 格式，端点 `/anthropic/v1/messages` |

**协议结论**：DeepSeek / GLM / MiniMax 走 OpenAI 兼容协议（复用 `LLMClient` openai 分支 + 自定义 `base_url`）；**LongCat 走 Anthropic 协议**（复用 anthropic 分支 + `base_url=https://api.longcat.chat/anthropic`，SDK 拼 `/v1/messages` 命中 `/anthropic/v1/messages` 端点）。地址与模型名均来自各厂商官方文档（见 `docs/api/`）。

## 7. 业务流程

### 7.1 首次进入

```
用户进入「AI 模型配置」
  → 后端发现 llm_provider_configs 表为空
  → 种入 4 条预置厂商记录（is_active=False, api_key=None, status='unknown'）
  → 前端展示 4 行，Key 状态「未配置」
```

### 7.2 配置并激活

```
点击某厂商「编辑」→ 填 API Key（必填）、可改接入地址与模型 → 保存
  → Key 加密入库，status 置 'unknown'
点击「测试连接」
  → 后端解密 Key，发轻量 chat 探测
  → 成功：status='valid'；失败：status='invalid' + 错误原因
点击「激活」（仅 status=valid 可激活）
  → 该行 is_active=True，其余行 is_active=False
  → LLM 客户端单例失效，下次调用按新配置重建
  → 顶部「当前使用」卡更新
```

### 7.3 切换厂商

```
激活另一家 → 原激活行 is_active=False → 新行 is_active=True
  → 客户端单例失效重建
  → 所有 AI 能力立即走新厂商
```

### 7.4 AI 能力调用链路（切换后）

```
学习路线生成 / 打卡生成 / 作业评改
  → service 调 get_active_llm_provider(session) 读激活配置
  → get_llm_client(config) 取/建客户端单例
  → LLMClient.chat / chat_stream（OpenAI 兼容协议 + 自定义 base_url）
```

## 8. 边界与降级

| 场景 | 处理 |
|------|------|
| 无任何激活厂商 | AI 调用回退到 `.env` 的 `LLM_*`；若 `.env` 也无可用 Key，抛 `LLMError`（code=3001），前端提示「请先到 AI 模型配置激活一家厂商」 |
| 激活厂商 Key 失效（401/403） | 调用时报 `LLMError`；前端提示「当前厂商 Key 失效，请到 AI 模型配置更新或切换」 |
| 厂商不支持 strict JSON Schema 结构化输出 | 降级为「prompt 要求返回 JSON + 文本解析」（复用现有 anthropic 分支的降级思路，见技术方案 4.3） |
| 测试连接超时 | status 置 'invalid'，提示「连接超时，检查接入地址或网络」 |
| 删除当前激活厂商 | 拦截：需先激活另一家，或确认后置 is_active=False 回退 .env |

## 9. 权限与安全

- 本期为本地 MVP 工具，无多用户权限体系；配置页与现有「接口配置」同层级，无额外鉴权
- API Key 加密存储（Fernet，密钥来自 `settings.secret_key`），与破局 Token 共用加密基础设施
- 对外接口一律脱敏返回（末 4 位），明文 Key 仅在写入时短暂存在于内存

## 10. 验收标准

- [ ] 进入页面看到 4 家预置厂商，Key 状态「未配置」
- [ ] 填入任一厂商真实 Key → 测试连接成功 → 状态变「可用」
- [ ] 激活后，生成学习路线 / 打卡 / AI 评改均实际调用该厂商并成功
- [ ] 切换激活厂商后，下一次 AI 调用立即走新厂商（无需重启）
- [ ] Key 在数据库中为密文，接口返回为脱敏
- [ ] DB 无激活厂商时，AI 调用回退 `.env` 配置不报错
