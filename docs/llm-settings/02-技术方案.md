# AI 模型配置 — 技术方案

> 版本：v1.0　　日期：2026-07-04
> 关联：`app/ai/llm_client.py`、`app/services/settings_service.py`、`app/api/settings.py`、`app/models/settings.py`

---

## 1. 现状分析

### 1.1 LLM 配置链路

```
.env (LLM_PROVIDER/LLM_API_KEY/LLM_MODEL/LLM_TIMEOUT)
  → app/config.py Settings
  → get_llm_client(settings) 单例（key = provider+api_key+model+timeout）
  → LLMClient(provider, api_key, model, timeout)
        ├─ anthropic 分支：anthropic.Anthropic(api_key, timeout)
        └─ openai 分支：openai.OpenAI(api_key, timeout)   ← 未传 base_url
```

**关键缺陷**：
1. 配置只在 `.env`，运行时不可改、不可在 UI 配置。
2. `openai.OpenAI()` 未传 `base_url`，只能连 OpenAI 官方，无法连国内厂商。
3. 单例缓存 key 不含 `base_url`，切换厂商后不会重建。

### 1.2 可复用的破局 settings 模式

`app/services/settings_service.py` 已实现一套成熟范式：
- DB 表 `poju_configs`（全局唯一记录）
- Fernet 对称加密（`_ensure_fernet_key(secret_key)`，SHA-256 → urlsafe base64）
- 脱敏输出（`_mask_token`，末 4 位）
- `test_connection` 探测 + 状态字段（`valid/invalid/unknown` + `last_checked_at`）
- API：`GET / PUT /token / PUT /base-url / POST /test`

**本方案复用该范式的全部基础设施**（加密、脱敏、状态机、test 模式），仅数据模型不同：破局是「全局单条」，LLM 是「多条 + 激活标记」。

## 2. 总体设计

### 2.1 核心决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 协议 | 按厂商分：OpenAI 兼容 + Anthropic | DeepSeek/GLM/MiniMax 走 openai 分支；LongCat 走 anthropic 分支；均需自定义 base_url |
| 配置存储 | DB 表 `llm_provider_configs` | 运行时可改、可存多条、支持 UI |
| Key 加密 | 复用 Fernet + `secret_key` | 与破局 Token 一致，不引入新密钥 |
| 激活机制 | `is_active` 字段，全局仅一条 True | 简单可靠，切换 = 改两行 |
| 客户端单例 | key 加入 `base_url`，激活变更即失效重建 | 切换即时生效 |
| 向后兼容 | DB 无激活配置时回退 `.env` `LLM_*` | 不破坏现有部署 |

### 2.2 架构分层

```
前端 pages/LLMSettings.tsx
  └─ api/llmSettings.ts + hooks/useLLMSettings.ts
       └─ HTTP /api/settings/llm/*
后端 app/api/settings.py（新增 llm 子路由，或新文件 llm_settings.py）
  └─ app/services/llm_settings_service.py（新建，复用加密/脱敏工具）
       └─ app/models/settings.py 新增 LlmProviderConfig
       └─ app/ai/llm_client.py 改造（加 base_url、单例 key、降级）
调用方 grading/checkin/route service
  └─ get_active_llm_provider(session) → get_llm_client(config)
```

class LlmProviderConfig(Base):

    is_preset: Mapped[bool] = mapped_column(
        Boolean, default=False, nullable=False, comment="是否预置厂商(预置不可删除基础信息)"
    )
    is_active: Mapped[bool] = mapped_column(
        Boolean, default=False, nullable=False, comment="是否当前激活"
    )
    key_status: Mapped[str] = mapped_column(
        String(20), default="unknown", nullable=False, comment="Key 状态: valid/invalid/unknown"
    )
    last_checked_at: Mapped[Optional[datetime]] = mapped_column(DateTime, nullable=True)
    created_at: Mapped[datetime] = mapped_column(DateTime, server_default=func.now(), nullable=False)

## 4. LLMClient 改造（`app/ai/llm_client.py`）

### 4.1 构造函数加 `base_url`

```python
class LLMClient:
    def __init__(
        self,
        provider: str,
        api_key: str,
        model: str,
        timeout: int = 60,
        base_url: Optional[str] = None,   # 新增
    ) -> None:
        self.provider = provider.lower()
        self.model = model
        self.timeout = timeout
        self.base_url = base_url

        if self.provider == "anthropic":
            import anthropic
            kwargs = {"api_key": api_key, "timeout": timeout}
            if base_url:
                kwargs["base_url"] = base_url
            self._client = anthropic.Anthropic(**kwargs)
        elif self.provider in ("openai", "openai_compatible"):
            import openai
            kwargs = {"api_key": api_key, "timeout": timeout}
            if base_url:
                kwargs["base_url"] = base_url
            self._client = openai.OpenAI(**kwargs)
        else:
            raise LLMError(f"不支持的 llm_provider: {provider}")
```

> `chat` / `chat_stream` / `_chat_text` / `_chat_structured` / `_stream_openai` 内部逻辑不变——openai SDK 的 `chat.completions.create` 调用方式与 base_url 无关，base_url 在客户端构造时绑定。

### 4.2 单例工厂改造

```python
_client_singleton: Optional[LLMClient] = None
_singleton_key: Optional[tuple] = None

def get_llm_client(
    provider: str,
    api_key: str,
    model: str,
    timeout: int = 60,
    base_url: Optional[str] = None,
) -> LLMClient:
    """单例按 (provider, base_url, api_key, model, timeout) 缓存，任一变化即重建。"""
    global _client_singleton, _singleton_key
    key = (provider, base_url, api_key, model, timeout)
    if _client_singleton is None or _singleton_key != key:
        _client_singleton = LLMClient(provider, api_key, model, timeout, base_url)
        _singleton_key = key
    return _client_singleton
```

> **注意**：原签名 `get_llm_client(settings)` 改为显式参数。调用方不再传 `settings`，而是传从 DB 读出的激活配置（见 §6）。这样切换厂商时 key 变化，单例自动重建。

### 4.3 结构化输出降级（openai 分支）

现有 openai 分支用 `response_format={"type":"json_schema","strict":True}`。部分国内厂商对 strict json_schema 支持不完整（可能报错或忽略）。增加降级：

```python
async def _chat_structured(self, system, messages, schema, temperature) -> BaseModel:
    schema_json = schema.model_json_schema()
    if self.provider == "anthropic":
        ...  # 保持现有 tool_use + 降级逻辑不变
    else:
        try:
            # 优先尝试 strict json_schema
            resp = await anyio.to_thread.run_sync(
                lambda: self._client.chat.completions.create(
                    model=self.model,
                    messages=[{"role":"system","content":system}, *messages],
                    temperature=temperature,
                    response_format={
                        "type":"json_schema",
                        "json_schema":{"name":schema.__name__,"schema":_json_schema_to_strict(schema_json),"strict":True},
                    },
                )
            )
            content = resp.choices[0].message.content or ""
            data = json.loads(content)
            return schema.model_validate(data)
        except Exception as e:
            # 厂商不支持 strict json_schema → 降级：prompt 要求 JSON + 文本解析
            logger.warning("strict json_schema 失败，降级纯 JSON 解析: %s", e)
            prompted = system + "\n\n必须返回严格符合下述 JSON Schema 的 JSON，不要任何额外文本。"
            resp = await anyio.to_thread.run_sync(
                lambda: self._client.chat.completions.create(
                    model=self.model,
                    messages=[{"role":"system","content":prompted}, *messages],
                    temperature=temperature,
                )
            )
            content = resp.choices[0].message.content or ""
            # 兜容：剥离 ```json 包裹
            content = content.strip().strip("`").lstrip("json").strip()
            data = json.loads(content)
            return schema.model_validate(data)
```

降级路径仍校验失败 → 抛 `ValidationError` → 由上层 `chat` 重试（现有机制）。

## 5. Service 层（`app/services/llm_settings_service.py` 新建）

复用 `settings_service.py` 的加密/脱敏工具（建议把 `_ensure_fernet_key` / `_mask_token` 提取到 `app/core/crypto.py` 共用，或在新 service 内复用）。

class LLMSettingsService:
    def __init__(self, session: AsyncSession, settings: Settings):
        self.session = session
        self._fernet = Fernet(_ensure_fernet_key(settings.secret_key))

    # 列表（脱敏）

    # 新增 / 编辑（api_key 明文入参，密文入库；不传 api_key 则不动）
    async def create_provider(self, payload: LlmProviderCreate) -> LlmProviderOut: ...
    async def update_provider(self, id: int, payload: LlmProviderUpdate) -> LlmProviderOut: ...

    # 删除（预置厂商禁止删除，可加 is_preset 校验）

    # 激活：置目标 is_active=True，其余 False

    # 供调用方使用：取当前激活配置（无激活则返回 None，由调用方回退 .env）

### 5.1 测试连接探测

```python
async def test_provider(self, id: int) -> ConnectionResult:
    cfg = await self._get(id)
    if not cfg.api_key:
        raise ValidationError("请先填写该厂商的 API Key")
    plaintext = self._decrypt(cfg.api_key)
    client = LLMClient(
        provider=cfg.protocol, api_key=plaintext,
        model=cfg.model, timeout=30, base_url=cfg.base_url,
    )
    try:
        # 轻量探测：1 token 级别的 hello
        text = await client.chat(system="你是测试助手", messages=[{"role":"user","content":"ping"}])
        cfg.key_status = "valid"
        cfg.last_checked_at = datetime.now(timezone.utc)
        await self.session.commit()
        return ConnectionResult(valid=True, message="连接成功")
    except Exception as e:
        cfg.key_status = "invalid"
        cfg.last_checked_at = datetime.now(timezone.utc)
        await self.session.commit()
        raise LLMError(f"连接失败: {e}")
```

### 5.2 激活的原子性

```python
async def activate_provider(self, id: int) -> LlmProviderOut:
    cfg = await self._get(id)
    if cfg.key_status != "valid":
        raise ValidationError("仅可激活已通过测试的厂商")
    # 其余全部置 False
    await self.session.execute(
        update(LlmProviderConfig).where(LlmProviderConfig.id != id).values(is_active=False)
    )
    cfg.is_active = True
    await self.session.commit()
    # 单例失效：清空 get_llm_client 缓存
    _reset_llm_client_singleton()
    return self._to_out(cfg)
```

> `_reset_llm_client_singleton()` 为 `llm_client.py` 新增的模块级函数，置 `_client_singleton=None`，确保下次调用按新激活配置重建。

## 6. 调用方改造

现有调用 `get_llm_client(settings)` 的 service（`grading_service` / `checkin_service` / `route_service`）改为：

```python
from app.services.llm_settings_service import LLMSettingsService
from app.ai.llm_client import get_llm_client

async def some_ai_call(session, settings, ...):
    llm_svc = LLMSettingsService(session, settings)
    active = await llm_svc.get_active_provider()

    if active is not None and active.api_key:
        plaintext = llm_svc.decrypt(active.api_key)
        client = get_llm_client(
            provider=active.protocol, api_key=plaintext,
            model=active.model, timeout=settings.llm_timeout,
            base_url=active.base_url,
        )
    else:
        # 兜底：.env 配置
        client = get_llm_client(
            provider=settings.llm_provider, api_key=settings.llm_api_key,
            model=settings.llm_model, timeout=settings.llm_timeout,
            base_url=None,
        )
    result = await client.chat(system, messages, response_schema=...)
```

> 为减少重复，可在 `LLMSettingsService` 封装一个 `get_active_client(timeout)` 方法，统一上述逻辑，调用方一行 `client = await llm_svc.get_active_client()` 即可。

## 9. 安全

- Key 加密：Fernet，密钥派生自 `settings.secret_key`（SHA-256 → urlsafe base64），与破局 Token 同源
- 脱敏：对外仅 `api_key_masked`（末 4 位）+ `has_api_key` 布尔
- 写入：明文 Key 仅在请求处理期短暂存在，落库即密文
- 日志：禁止打印明文 Key；测试连接失败日志只记错误类型与厂商名

## 10. 兼容性与迁移

- `.env` 的 `LLM_*` 配置保留，作为 DB 无激活厂商时的兜底（§6）
- 现有 anthropic 分支与 `.env` anthropic 配置保留可用
- 迁移 `0002` 仅新增表，不改既有表，向后安全
- 首次启动若 `llm_provider_configs` 表为空，service 层 `list_providers` 自动种入 4 条预置记录（兜底，即使迁移种子未执行也能自愈）

## 11. 风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| 厂商对 strict json_schema 支持不一 | 结构化输出（评改/路线/打卡）失败 | §4.3 降级为 prompt+解析；已验证 DeepSeek/GLM 支持较好 |
| LongCat 接入信息不确定 | 预置 base_url/model 可能不符 | UI 可编辑；预置标注「以官方文档为准」；用户填正确值即可 |
| 切换激活时正在进行的 AI 调用 | 单例被清空，旧 client 引用仍可用完本次调用 | 可接受：新调用走新配置，旧调用用旧引用完成 |
| `.env` 兜底与 DB 配置混淆 | 用户以为切了厂商实际走 .env | 顶部「当前使用」卡明确显示来源（DB 激活 / .env 兜底） |
| Key 解密失败（secret_key 变更） | 该厂商不可用 | 复用破局 Token 的 `ValidationError` 提示「请重新配置」 |

## 13. 测试要点

- 迁移 upgrade/downgrade 正确，种子 4 条写入
- 加密 round-trip：写入 → 读取脱敏 → 解密还原
- 激活原子性：激活 A 后 B 的 is_active=False
- 单例重建：激活切换后，下一次 `get_llm_client` 返回新 client
- .env 兜底：DB 无激活时回退 `.env`
- 结构化输出降级：mock 厂商不支持 strict 时走 prompt 解析
- 测试连接：成功/失败分别更新 key_status
